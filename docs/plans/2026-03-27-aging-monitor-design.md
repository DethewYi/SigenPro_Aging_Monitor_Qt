# 储能产品老化监控系统 — 设计方案

## 1. 项目概述

单机版 Qt 桌面应用，用于储能行业产品老化测试的全流程监控与管理。

### 监控产品

- PCS 逆变器、PACK 包、DCDC 变换器、BMU、BC
- 涵盖整机与 PCBA 级别

### 核心能力

- 100-500 台设备同时监控
- 实时数据采集、曲线展示、报警提示
- 仪器控制（电源、接触器上下电）
- 扫码绑定（SN/PN 与通道关联）
- 测试模板管理
- PDF/Excel 报表生成
- 多主题 + 多语言（中/英）

## 4. 界面设计

### 4.1 整体布局

- 左侧导航栏 + 右侧内容区
- 支持多主题切换：深色（默认）、浅色、蓝灰工业风、高对比度
- 支持多语言切换：中文（默认）、英文，实时生效无需重启
- 主题和语言偏好持久化存储

### 4.2 设备总览（首页）

- 顶部统计栏：在线设备数、离线数、报警数、正在测试数（数字卡片）
- 中部设备网格：每台设备一张卡片
  - 显示：产品型号、SN、当前状态、关键参数（电压、电流、温度）
  - 卡片颜色：绿色测试中、黄色待机、红色报警、灰色离线
- 支持按状态、产品类型筛选，支持搜索

### 4.3 设备详情页

- 左栏：实时数据面板（数值列表）+ 报警阈值设置
- 右栏：多通道曲线图（电压、电流、温度、功率），支持缩放和拖拽
- 底部：测试方案信息 + 控制按钮（启动/暂停/停止）

### 4.4 报警面板

- 报警列表，按时间倒序
- 每条记录：时间、设备名称、报警参数、当前值、阈值
- 支持报警确认操作

### 4.5 数据查询与报表

- 按设备/时间范围/产品类型查询历史测试记录
- 查询结果可查看回放曲线
- 一键导出 PDF/Excel 报告

## 5. 通信层

### 5.1 通信方式

| 方式 | 场景 | 说明 |
|------|------|------|
| TCP Socket | 主要方式 | 设备通过以太网直连 |
| CAN | 辅助方式 | 通过 CAN-以太网转换器接入 |
| RS485 | 辅助方式 | 通过串口服务器转以太网，或本地串口直连（备用） |

### 5.2 通信管理

- 为每台设备分配独立收发线程，通过线程池管理 100-500 个连接
- 连接断开自动重连（指数退避，最多重试 N 次）
- 心跳检测，超时标记离线
- 数据帧 CRC/LRC 校验，错误帧丢弃并计数

### 5.3 数据采集流程

1. 设备管理模块维护连接配置（IP、端口、协议类型、产品型号）
2. 数据解析按产品类型通过配置表区分字段映射
3. 解析后统一成标准结构体：设备ID、时间戳、参数键值对、通信状态
4. 推送到全局数据总线（信号槽），界面层订阅关心的数据

## 6. 协议扩展接口（预留）

### 6.1 设计原则

所有协议（监控协议 + 控制协议）通过**插件化架构**实现扩展，新增协议不需要修改主程序代码。

### 6.2 数据采集协议接口

```cpp
class IProtocolParser {
public:
    virtual ~IProtocolParser() = default;
    virtual bool parse(const QByteArray& rawData, DeviceData& output) = 0;
    virtual QByteArray buildRequest(const QString& cmd) = 0;
    virtual QString protocolName() const = 0;
};
```

- 每种设备协议实现此接口，编译为独立 DLL 插件
- 运行时根据通道配置动态加载对应插件
- 新增设备协议：实现接口 → 编译 DLL → 配置文件关联通道

### 6.3 仪器控制协议接口

```cpp
class IInstrumentController {
public:
    virtual ~IInstrumentController() = default;
    virtual bool connect(const DeviceConfig& config) = 0;
    virtual bool powerOn(int channel) = 0;
    virtual bool powerOff(int channel) = 0;
    virtual bool setVoltage(int channel, double voltage) = 0;
    virtual bool setCurrent(int channel, double current) = 0;
    virtual bool readStatus(int channel, ChannelStatus& status) = 0;
    virtual QString protocolName() const = 0;
};
```

- 电源、接触器各有独立控制协议适配器（共 4-5 种）
- 同样通过插件 DLL 动态加载

### 6.4 插件管理器

- 负责扫描 plugins/ 目录下的 DLL
- 按配置文件注册协议名到插件的映射
- 提供统一工厂方法创建协议实例

## 7. 仪器控制模块

### 7.1 通道管理

- 每个测试工位为一个"通道"，通道与物理设备（电源、接触器）绑定
- 通道状态：空闲 / 已绑定 / 测试中 / 故障

### 7.2 上料流程

```
操作员扫码 → 识别SN+PN → 匹配空闲通道 → 绑定 → 自动选择测试模板 → 待启动
```

- 扫码枪通过串口/USB 接入，软件监听扫码输入
- SN 匹配 PN，自动关联测试模板
- 绑定关系持久化，支持断电恢复

### 7.3 下料流程

```
测试结束/手动停止 → 断开接触器 → 关闭电源 → 解绑通道 → 记录SN测试结果 → 通道释放
```

### 7.4 控制安全

- 上电/下电操作需二次确认
- 操作日志记录所有控制指令
- 异常时自动下电保护

---

## 8. 测试流程

### 8.1 测试模板

每个模板包含：
- 基本信息：模板名称、适用产品型号
- 采集参数：监控参数列表 + 采集频率
- 测试时长：总时长
- 报警阈值：各参数上限/下限
- 测试阶段（可选）：支持分段，每阶段可设不同阈值

模板支持预设 + 操作员微调。

### 8.2 完整执行流程

```
扫码绑定 → 选择/调整模板 → 启动电源/接触器上电 → 开始采集 →
实时监控/报警判定 → 测试结束(到时/手动) → 断电下电 → 解绑 → 生成报告
```

### 8.3 测试结果

- 通过：全程无报警，数据完整
- 异常：出现过报警，报告中标记异常时段
- 中断：手动停止或通信中断导致数据缺失

## 9. 数据存储

### 9.1 本地 SQLite（实时层）

- 按天分表：device_data_YYYYMMDD
- 批量写入：每 1-2 秒聚合插入，减少 IO
- 保留策略：默认 30 天，可配置
- 用途：实时曲线、界面刷新、快速查询

### 9.2 远程数据库（归档层）

- MySQL/PostgreSQL，按月分表
- 同步策略：定期（每小时/每天）批量同步
- 保留策略：长期归档，可配置
- 用途：历史查询、报表、数据共享

### 9.3 元数据表

| 表名 | 内容 |
|------|------|
| devices | 设备基础信息（ID、型号、IP、通道、协议类型） |
| channels | 通道配置（通道号、电源/接触器关联、绑定SN/PN） |
| test_templates | 测试方案模板 |
| test_records | 测试记录（设备ID、SN、起止时间、结果） |
| alarms | 报警记录 |

## 10. 报表生成

- 测试结束后自动生成，或手动触发
- PDF 报告：测试信息 + 关键数据统计 + 曲线截图 + 结论
- Excel 报告：原始数据明细 + 统计汇总
